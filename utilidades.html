Border radius

Utilidades .rounded-* para redondear cualquier contenedor dentro del scope: cards, inputs, imágenes, badges, bloques de código y contenedores de modal. Siguen el nombre de Bootstrap y usan los tokens --radius-*, así que cambiar un token redimensiona toda la escala.

HTML 
<div class="rounded-0">Sin radio</div>
<div class="rounded-1">4px</div>
<div class="rounded-2">8px</div>
<div class="rounded-3">16px</div>
<div class="rounded-4">24px</div>
<div class="rounded-circle">50%</div>
<div class="rounded-pill">999px (extremo a extremo)</div>

Escala numérica

Cada número apunta a un token, no a un valor fijo. Si se reescala --radius-lg en el tema, todas las cajas con .rounded-3 cambian juntas.

Redondean solo las esquinas indicadas, útil cuando un radio se une a un borde existente (por ejemplo una imagen pegada al borde de un bloque). Todas usan --radius-md (8px); combina con .rounded-* numérico si necesitas otro valor.

Notas de uso

Las utilidades van scoped a .node-scope y usan !important, igual que las de espaciado. Eso significa que ganan a cualquier radio definido por el componente, así que conviene aplicarlas en la envoltura y no peleando contra una variante específica. Si necesitas el radio exacto de un componente (por ejemplo .info-relevante__logo), usa la clase del componente: las utilidades están pensadas para contenedores genéricos y ajustes puntuales.

Grosor de borde

Utilidades .border-* para poner a la vez el grosor y el estilo de un borde. Bootstrap ya trae .border-1 … .border-5, pero solo declaran border-width: sin border-style no se dibuja, así que hoy para tener un borde de 2px hay que encadenar .border + .border-2. Estas declaran el shorthand completo, de modo que una sola clase basta y el grosor nunca se separa del estilo.

HTML 
<div class="border-0">Sin borde</div>
<div class="border-1 border-color-gray-light">1px</div>
<div class="border-2 border-color-gray-light">2px</div>
<div class="border-3 border-color-gray-light">3px</div>
<div class="border-4 border-color-gray-light">4px</div>
<div class="border-5 border-color-gray-light">5px</div>

Escala

ClaseDeclaraciónUso típico
.border-0border: 0Quitar el borde. Gana a cualquier .border-*, así que sirve para apagar el que traiga un componente.
.border-1border: solid 1pxEl grosor por defecto del proyecto: separadores, tarjetas, contenedores.
.border-2border: solid 2pxBordes con más presencia, estados activos.
.border-3border: solid 3pxPoco uso en el proyecto; reservado.
.border-4border: solid 4pxIgual que el anterior, reservado.
.border-5border: solid 5pxIgual que el anterior, reservado.

En el framework el borde se usa a 1px en 38 sitios y a 2px en 2; de ahí que la escala llegue hasta 5 para tener la misma cabecera que Bootstrap y no cambiar de nombres si algún día hace falta.

Notas de uso

  • El color va aparte. El shorthand deja el borde en currentColor, así que sin .border-color-* sale del color del texto —igual que los componentes que declaran border: 1px solid sin color, como .info-relevante y .chip. Combina con .border-color-*.
  • Van antes que .border-color-* en el archivo, a propósito. Las dos familias son !important y tienen la misma especificidad, así que gana la que aparece después en la hoja: como el grosor va primero, el color siempre le gana, sea cual sea el orden de las clases en el HTML. Si alguien mueve este bloque, hay que comprobar que .border-color-* siga debajo.
  • .border-0 está al final del bloque por el mismo motivo, pero al revés: así le gana a .border-1 … .border-5 y class="border-2 border-0" sí quita el borde, mientras que el color sigue mandando.
  • Pisan al .border de Bootstrap ((0,2,0) contra (0,1,0)), así que class="border border-3" da 3px y no 1px.
  • No hay variantes direccionales (.border-top, .border-start…). Para un lado concreto usa el border-top del componente o una regla propia.

Utilities de color de borde para cualquier elemento interno del scope (chips, badges, cards, etc.). Requieren que el elemento tenga un borde definido (los chips ya traen border: 1px solid en su base; solo se combina con .border-color-*). Sin .border-color-*, el borde toma el color del texto (currentColor).

Contraste de --color-blue-green-medium (#2E8F78): da 3.95:1 sobre blanco. Cumple AA para texto grande y para componentes gráficos (borde, separador), pero no llega al 4.5:1 que pide AA para texto normal. Como fondo, el texto blanco encima también queda en 3.95:1, así que ahí solo usarlo con texto grande o con --color-blue-green-dark (#0F685E, 6.64:1) como color de texto. La escala completa queda así sobre blanco: #8ECBB8 1.84:1 (solo decorativo), #3FAE95 2.73:1 y #2E8F78 3.95:1 (este), #0F685E 6.64:1 (el único que cumple AA para texto normal). Para texto normal sobre blanco, el color de la familia es --color-blue-green-dark.

Tonos -dark y -extra-dark: estos 14 tokens existen para que el hover de cada boton tenga un color propio en vez de un hex suelto. Todos dan 4.5:1 o más contra texto blanco, así que los rellenos que los usan cumplen AA. Ver Catálogo de botones.

Se aplican con !important. Las 48 utilidades declaran border-color: … !important para ganar siempre frente al color de borde que traiga el componente. Así una sola clase de color reescribe el borde de cualquier variante sin importar su especificidad ni el orden en el CSS. Consecuencia práctica: solo cambia el color; el grosor, el estilo (solid / dashed) y el radio siguen viniendo del componente.

Scroll reveal

Animaciones que se disparan al entrar o salir de pantalla. Funciona con IntersectionObserver nativo, sin jQuery y sin build.

Se distribuye como archivo aparte y no forma parte del framework, precisamente para que un proyecto que no lo use no cargue ni un byte: assets/css/score-reveal.css y assets/js/score-reveal.js. Esta página de documentación es la única que los carga.

Contenido visible por defecto. A diferencia de librerías como AOS, aquí el CSS nunca oculta nada por sí solo. Lo único que puede quedar oculto es un elemento que lleve la clase .is-reveal-pending, y esa clase la añade el propio JavaScript. Si el JS no carga, falla, o el navegador no soporta IntersectionObserver, todo el contenido se ve con normalidad. Además, con prefers-reduced-motion: reduce activo, la animación se anula y el contenido se muestra estático.

Uso básico

Añade .reveal al elemento. La dirección por defecto es up.

HTML 
<section class="node-scope">
    <div class="reveal" data-reveal="up">Entra desde abajo</div>
    <div class="reveal" data-reveal="left">Entra desde la derecha</div>
    <div class="reveal" data-reveal="scale">Entra con un leve zoom</div>
</section>

Modos: entrada, salida o ambas

Se eligen con data-reveal-mode. El modo por defecto es in.

ModoComportamientoCuándo usarlo
in default Oculta lo que aún no está en pantalla, anima al entrar y se queda visible. Deja de observar el elemento, así que no se repite. El caso habitual: revelar secciones al hacer scroll sin volver a ocultarlas.
both Igual que in, pero además vuelve a ocultarse al salir de pantalla. Se repite en cada cruce. Efecto de alternar: el contenido “acompaña” al scroll en ambos sentidos.
out Arranca siempre visible, no oculta nada al iniciar, y a partir de ahí alterna igual que both. Cuando prefieres que el contenido esté disponible desde el primer momento y solo quieras que se desvanezca al alejarte.
HTML 
<!-- Solo entrada (default): se queda visible para siempre -->
<div class="reveal" data-reveal="up"></div>

<!-- Entrada y salida: alterna en cada cruce -->
<div class="reveal" data-reveal="up" data-reveal-mode="both"></div>

<!-- Solo salida: arranca visible, se desvanece al salir -->
<div class="reveal" data-reveal="up" data-reveal-mode="out"></div>

Integración en Drupal

Tres vías, de menos a más control. La librería expone ScoreReveal como API pública para poder reinicializarla.

1. Asset Injector — sin escribir código. Crea un inyector CSS que apunte a score-reveal.css y otro JS a score-reveal.js, y aplícales una condición por ruta o tipo de contenido. Es la vía recomendada cuando sólo quieres activar el efecto en ciertas páginas.

2. Bloque HTML — pega el JS dentro del propio bloque, entre <script> y </script>. Como la librería es autocontenida, funciona igual. Para el CSS añade un <link> al archivo, o configura Asset Injector sólo para el CSS.

Drupal · bloque HTML 
<!-- En un bloque HTML de Drupal: -->
<link rel="stylesheet"
      href="/themes/tu-tema/assets/css/score-reveal.css">

<div class="reveal" data-reveal="up">Entrará al hacer scroll</div>

<script src="/themes/tu-tema/assets/js/score-reveal.js"></script>

3. Módulo propio — la forma más limpia. Declara la librería en *.libraries.yml y adjúntala sólo donde aplique con attach_library() dentro de un build() de plugin de bloque, o en el .twig del bloque con {{ attach_library('mi_modulo/score-reveal') }}. Así el archivo entra en el caché de agregación de Drupal y la versión se invalida sola al cambiarla.

Drupal · libraries.yml 
score-reveal:
  version: 1.x
  css:
    theme:
      assets/css/score-reveal.css: {}
  js:
    assets/js/score-reveal.js: { attributes: { defer: true } }

Drupal AJAX. Si un behavior reemplaza el DOM (filtros expuestos de una vista, un formulario, una carga por scroll), los elementos nuevos necesitan inicializarse. Usa la API pública, que es idempotente y no duplica observadores:

JavaScript 
(function ($, Drupal) {
    'use strict';

    Drupal.behaviors.scoreReveal = {
        attach: function (context) {
            if (window.ScoreReveal) {
                window.ScoreReveal.init({ scope: context });
            }
        }
    };

}(jQuery, Drupal));

También puedes pasar opciones: ScoreReveal.init({ scope, threshold, rootMargin }). Y si integras la librería junto a otro script y una excepción impide que los observadores lleguen a dispararse, ScoreReveal.releaseAll() revela de golpe todo lo pendiente como red de seguridad.
